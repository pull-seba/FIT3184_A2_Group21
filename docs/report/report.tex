\section{Introduction}

Aussie EcoGuard is a centralised, multi-cloud serverless system where researchers and citizens upload, automatically classify and search media files, helping track invasive pests and find lost pets across Australia.

\section{Architecture}

The architecture in Figure~\ref{fig:architecture} spans AWS (\code{us-east-1}) and GCP (\code{us-east1}). AWS hosts the Cognito user and identity pools, a Lex V2 chatbot with its fulfilment Lambda, an SNS publisher Lambda, and Rekognition \code{DetectLabels}. GCP hosts API Gateway, Python 3.12 Cloud Run functions, Firestore, Cloud Storage, Eventarc, Pub/Sub and Vertex AI. The Angular 21 app runs from its local development server.

An upload starts when the browser computes the file's SHA-256 hash and requests a signed PUT URL. If no duplicate exists, the file uploads directly to Cloud Storage. Through Eventarc, the storage event starts two Cloud Run services, which can finish in either order: one verifies the hash, writes the record and makes a compressed, aspect-ratio-preserving OpenCV thumbnail; the other detects species tags. Videos yield one frame per 10 seconds and a poster thumbnail, with frames reaching the tagging service through a \code{frames-ready} topic. Tag changes fire a Firestore trigger that publishes alerts to Pub/Sub.

The system uses four cross-cloud links:
\begin{enumerate}
  \item The browser sends the Cognito ID token to the GCP API Gateway, which checks its signature against the user pool's public keys, its issuer and its audience before any function runs.
  \item The Lex fulfilment Lambda calls the GCP API with the signed-in user's Cognito ID token. The chat page sends it as a Lex request attribute, so Lex doesn't store it.
  \item For email alerts, a Pub/Sub push subscription sends a Google-signed OIDC token to an AWS Lambda, which validates the token before publishing to SNS with per-tag filter policies.
  \item The tagging and search-by-file functions exchange their Google identity tokens for temporary AWS credentials through Workload Identity Federation, on a role allowed only \code{rekognition:DetectLabels}. Image bytes are sent for analysis and are never stored on AWS. The subscriptions function makes the same exchange, on a role limited to the alert topic's subscribers.
\end{enumerate}

\section{Design Decisions and Trade-offs}

\begin{itemize}
  \item \textbf{Provider Split:} The specification requires AWS Cognito, Lex and SNS. Keeping files, data and compute together on GCP avoids storing files on two clouds.
  \item \textbf{Signed URLs:} Buckets stay private and no stored link expires, because URLs are signed per response. Uploads use \code{if-generation-match: 0} to block overwrites.
  \item \textbf{File Deduplication:} File IDs are the SHA-256 hash of the file bytes, so duplicates are caught by content, not file names or sizes.
  \item \textbf{Separate Buckets:} Thumbnails and frames go in a separate bucket, because storage triggers can't filter by prefix and would re-trigger the pipeline.
  \item \textbf{Video Tag Counting:} A video's count for each tag is the maximum found in any single frame. Summing would count the same animal once per frame.
  \item \textbf{Merge-only Firestore Writes:} Several functions write the same record, and events can arrive twice or in either order, so each function merges only its own fields.
  \item \textbf{Model Selection:} Amazon Rekognition was selected because it names the project's species directly, while a stock YOLO or MegaDetector would need a second species model. A \code{model\_label\_map} leaves out labels such as Amphibian and Canine, which also fired on tree frogs and on both foxes and dogs. The trade-off is a cross-cloud call per image.
  \item \textbf{Embeddings Strategy:} Vertex AI multimodal embeddings paired with Firestore vector search were chosen because images and text share a single embedding space: one model powers photo search and labels each sighting's colour for description search. It beat CLIP (a 1--2\,GB container), Titan Multimodal (also needs the federated AWS role) and Gemini Embedding 2 (its default 3072 dimensions exceed Firestore's limit).
  \item \textbf{Region Selection:} GCP uses \code{us-east1} because Firestore's location is fixed and Eventarc storage triggers must share their bucket's region. AWS services use the nearby \code{us-east-1}. The trade-off is higher latency for Australian users.
\end{itemize}

\section{Security}

Every backend route except CORS preflight requires a valid Cognito ID token, and Cloud Run services reject unauthenticated invocations. Each GCP function has its own least-privilege service account, and each Lambda its own IAM role. For example, \code{on\_tags\_changed} holds only \code{roles/pubsub.publisher} on the \code{tag-changes} topic and \code{roles/eventarc.eventReceiver}, and reads nothing from Firestore. No long-lived keys or tokens exist in the repository or frontend bundle. Because Pub/Sub can't sign AWS requests, the alert Lambda's URL is public and rejects any request without a valid Google token. Photos submitted for file and lost pet searches are processed in memory and never stored or indexed.

\section{Limitations and Future Work}

Rekognition undercounts groups of cane toads. In the 140-photo bake-off, photos with two or more animals got a count of 2+ for 100\% of pigs, 67\% of foxes, and 33\% each of toads and rabbits, with one over-count. A counting model could be added later through \code{config/model}. Also partly complete:

\begin{itemize}
  \item \textbf{Hosting:} The app runs on the Angular development server instead of Firebase Hosting, so it has no public address.
  \item \textbf{Temporary passwords:} Self sign-up verifies email by code, so only admin-created users receive a temporary password to change.
  \item \textbf{Search by file:} It accepts photos only; videos would need frame extraction during the request.
  \item \textbf{Lost pet search:} It filters by species and colour, not breed, because no model gives breeds.
  \item \textbf{Alerts:} A redelivered event can send a second email; deduplicating needs another Firestore collection.
\end{itemize}
